# WebArt 产品与生产约定

状态：执行中 · 2026-09-06

WebArt 的产品是**多个可预览、可下载、可修改使用的高质量单页网站模板**。用户最终获得完整网页源码；母版筛选、素材生成和技术实验是生产过程，不是商品。以已验收模板数量、整页质量、下载后可用性和单件生产成本衡量进展。

## 三层职责

| 层 | 交付职责 | 完成标准 |
|---|---|---|
| 模板集合 | 发现模板、独立预览、一个明确下载入口、用途与使用说明 | 只展示已验收且下载验证通过的版本 |
| 单个模板 | 一个完整、连贯、可修改的网页体验 | 以母版为设计基准，允许经过验证的局部调整；同一质量标准验收；每模板一个源码 ZIP |
| 内部生产线 | 筛选、拆解、替换、复刻、验收、打包 | 各阶段有输入、证据、结论；失败在上游止损 |

集合展示入口不应侵入已接受的模板画面。`public/templates.json` 是由台账生成的可下载条目数据，不代表集合展示页已经建成。现有根首页仍是 Design 001 的独立演示。

## 生产方法

2026-09-06 用户确认：每个模板收敛到 **2–5 屏**。所有不适合短页的内容、结构与交互均可删减或做局部调整，包括整段项目列表、招聘、订阅、重复介绍、冗长文案和长滚动。记录删改边界并检查新衔接；不再强制保留全部中间源站章节。Design 002 已获准按此流程开始新版本实现，旧拒绝稿仍不计入成品。

1. **小批筛选。** 每批最多快速检查 6 个候选，最多深入审查 3 个。已有完整证据优先。逐项记录结果后才开新批，重复候选必须说明新证据。
2. **筛选与基准评分。** 用统一网页质量表评估原站，达到 98+ 才准入；这是内部评审，不是外部认证分数。同时确认连续完整路径、可分发素材和移动端方案。含复杂 3D 的原站允许进入替换试验，不因技术不同自动淘汰。
3. **先试关键调整。** 列出保留项与调整项，例如实时 3D → 原创静态渲染图。先用小型可运行页面验证最影响质量的一处调整，连同相邻过渡一起看；再锁定开场、中段、过渡、收束四个完整审查状态。素材图本身不能代替页面验收。
4. **直接复刻目标版本。** 在复刻时同步完成批准的图片、文案、品牌和技术调整，避免先做一套完整 3D 再拆掉。每项调整记录原有作用、替代方式、影响范围和验收证据；保留成熟构图与整页节奏。没有完整来源的拼接和无关新设计仍禁止。
5. **同标准验收改后整页。** 原站与成品使用同一版本、同一权重的评分表，在对应视口与输入状态下分别评分；改为静态后仍照常评价视觉与交互的实际效果。检查真实滚动、过渡、任意位置、移动端和用户实际减少动态效果的设置，成品达到 97+、各主状态 95+、结尾与开场差距不超过 2 分、零关键缺陷才通过。相似度和技术复杂度不能代替质量。
6. **验证后交付。** 只有批准的源码版本能打包；独立解压安装构建成功后才进入公开目录。一个模板只发布一个可编辑源码包，集合数据由验证后的包生成。

批次上限是控制搜索范围，不是降低门槛。没有合格候选时，记录具体阻碍并结束当前批次；不伪造高分，也不自动无限开启下一批。

主流程：**筛选高分原站 → 列出调整并试验关键替换 → 直接复刻调整后的版本 → 用原站同一标准验收 → 交付新 design 模板。**

同一评分表见 `docs/PRODUCTION_PIPELINE.md` 的 Webpage Quality v2：构图与设计语言 30、视觉表现 25、整页一致性 20、动态与交互 10、响应式与任意状态 10、网页可用性 5。可追溯复刻关系、素材可分发性和源码包验证单独作为通过/不通过条件；不要求参考原站提供源码包，也不按是否使用 WebGL 加减分。不同版本的历史评分不用于计算前后分差。

## 可执行记录

- `webart.collection.json`：模板状态、来源记录、被批准源码指纹、当前包大小与哈希。状态必须有决策/QA依据。
- `docs/production/`：短小的候选结论和重启记录，避免依赖长对话。
- `docs/pages/`、`docs/references/`、`docs/assets/`、`docs/qa/`：每件模板的固定交接材料。
- `npm run collection:status`：查看实际库存与生产阶段。
- `npm run collection:check`：检查批准记录和源码版本；拒绝冻结项。
- `npm run release -- --id 001`：验证并发布一个已验收模板；不带 ID 则处理全部已验收模板。

命令只验证状态、证据路径、源码身份和交付物；它们不能自动认定作品是高分设计。模板必须先取得真实的视觉验收，再登记批准指纹。
