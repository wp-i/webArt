# WebArt 生产流程

文档职责：本文件规定制作与工程检查，视觉准入按 [品质协议](production/QUALITY_PROTOCOL.md)，常规整页渲染器与审核恢复按 [自动化边界](production/AUTOMATION_IMPLEMENTATION.md)。日期段落只覆盖其对应阶段；旧 Key/稿件状态不作为当前阻断。参考、试片、完整 QA 和常规实例化的要求分别适用，不把一次局部收尾许可延伸为常规生产源码修补许可。

当前版本v2，更新2026-10-18。用户明确评第一稿95、其余五稿约80，旧内部95判断失效。先执行[生产质量协议](production/QUALITY_PROTOCOL.md)和对应选择/试片/审查输入，再沿工程流程实施。用户确认静态内容配置、尽量降低LLM自主执行占比；[配置运行器](production/AUTOMATION_IMPLEMENTATION.md)现在实例化已完成双门和全QA的版本化完整模板，常规执行只替换受限内容，模型不再生成或修补页面代码。新风格的首次制作仍须独立走完整准入，不能复用旧80稿充库。独立API调用与当前会话证据审查是分别记录的执行方式；没有独立Key时可按现行证据队列继续，如实标注上下文与独立性限制，不宣称稳定获得95或已完成独立模型闭环。

## 1. 有预算的筛选

2026-10-12新增风格差异门：先读[当前风格对照](production/STYLE_MATRIX.md)，与最接近的既有稿核对开场构图、字体、色彩、素材语言、节奏及标志交互。开场构图和素材语言不得同时重复，至少三项结构性差异；只换行业名、照片或配色不准入。目录分类文字已由用户删除，不得恢复。

先确定用途、短文案角色与交互目标，再优先看具备成熟鼠标/滚动表现的工作室/服务/品牌短页。只从真实出站链接取URL，图库截图、旧奖项与图片数不证明当前质量。先查[参考索引](production/reference-index.json)：已拒绝域名跳过；重新查看必须有明确新证据并记录原因。本次008重查Focal的问题不能再发生。

快筛每批最多6站，单站浏览动作串行，最多3批/18站且总筛选目标15分钟；一旦找到一个合格母版停止搜索，只深入这一个。超过预算或无人通过就记录失败并结束本次运行，不无限换批。搜索/URL读取可并行，同一浏览器的前台、滚动、截图不能并行争抢当前页。

先以001判断主视觉和完整过程品质，再检查7工程条件：默认静止可看、信息直接显示、核心美感可保真、少量媒体可独立替换、短完整路径、原生输入/清楚手机方案、用户可修改。2026-10-13用户授权品质优先、必要的局部3D：材质/空间/形态是母版核心时允许实时几何及必要shader，不再因该技术形式自动跳过；不能通过删掉关键品质让普通替代物过门。试片须同时验证普通设备、手机、减少动态及渲染失败替代。核心不能保真则拒绝整个候选。技术形式、图片/视频数量和零生成不作为审美加分。

`scripts/inspect-reference.mjs`快筛只保存开场/metadata；等待字体和首屏图片并限定超时，视觉加载未完成标evidence-needed。域名转售/重定向检查后拒绝过期来源。只对唯一母版deep取完整路径和手机；无需给每个淘汰站生成四大截图。

## 2. 审查替换后、删减后的整页

母版默认首屏要能指出具体记忆点、位置、比例，手机与品牌/字体/素材替换后仍成立。弃用40/20/20/10/10自评分及“平均达到95”。使用v2七项成对比较：开场权威、字形/图像工艺、素材特异性、滚动编排、指针细节、整页收束、手机构图。一项重要差距即拒绝，工程功能不能补偿；用户95/约80校准优先。对照001品质，不复制其黑金/舞台。

**删减后必须保留可见的服务/作品/产品证据。** 不能把“漂亮首屏→FAQ→CTA”自动当成整页95；007正是这个漏项。也不能认为有三张图就一定惊艳；008中下段字体/编排仍普通。字体许可与替代字形、图片角色/裁切、结尾内容功能在实施前锁定，禁止到实现阶段再美化救场。

结论admitted / rejected / evidence-needed，一行记录即足够；失败也计入本轮数据。工艺简单、零媒体、构建通过均不加审美分。

## 3. 最终素材与四状态闸门

建立page brief、单母版reference map、asset plan和DECISIONS记录，再做开场/中段/真实过渡/收束的可运行状态。最终品牌、文案、可分发字体和实际媒体全部加载，至少1440×900与390×844。直接同时对照母版、成品及001；原图不等于页面、锚点不等于路径。

素材按[获取标准](assets/SOURCING_STANDARD.md)先查已授权库存，再有限筛选成品摄影/材质；逐张核对构图、光线、色彩、裁切和源码包分发许可，选定后本地保存并复用来源记录。库存复用不得让各稿长得一样。

仅在成品素材无法满足关键构图时生成，每角色一次、最多一次有明确构图原因的替换；仍不合适则停止，不围绕坏素材重设计。不以“新稿”自动触发生成，不复制母版图片。文件类型按实际字体签名/图片尺寸核验，不猜扩展名，不为不必要转换安装依赖。

四状态使用最终短文案及实际动效，记录来自母版的鼠标/局部反馈和有作用的滚动变化，说明桌面、触摸、键盘与减少动态方案；不适用项须有母版依据。首次与重复进入、正反滚动、中间进度均实际审看，可录短视频或连续帧。没有过程证据不得因截图好看就通过。

2026-10-14顺序修正：先完成母版完整八状态/真实过程及七维审查，执行`preflight-reference`；创建私有试片统一使用`begin-candidate`，它在参考通过前不写试片目录。之后才能按已批准的角色取得最终替换素材、锁图谱并制作试片。不能先做完试片再补参考审查。007本次整页母版及试片均拒绝，未创建正式替换或新ZIP。

reference及prototype两个v2品质门均通过才准许全面实现。存在核心删减、替换损失或一项明显低于001即停止；不能批准“做完以后再调”。既有006–010仅按精确源码/ZIP收据保留用户授权比较，不是新生产/重打包/品质放行例外。旧95内评不再有闸门效力。

## 4. 一次实现、有限收尾

只实现已锁定视觉与交互，复用不可见工程，不跨页套用显眼构图。普通滚动保留母版的渐变、揭示、局部视差等质感；默认内容完整，原生details/锚点可用但不能取代签名交互。删除无用途脚本，保留有视觉目的的轻量脚本。每段有新内容/视觉作用，同页不重复主图、主构图、巨型标题或节奏；素材不够就结束，不增章填空。占位文案只保留示例作用，长宣言、成组FAQ、营销段须证明必要性。

新完整模板首次制作最多一轮局部修正。核心结构/素材/签名交互要重做即记录筛选失败并停下。完成双门、完整QA、控件和故障替代检查后，使用同一可执行v2打包门登记版本化渲染器。常规生产不得局部改代码；发现问题须修改配置或登记新模板版本并复审。页面输入只携带本页合同、素材计划、选中参考和当前阶段证据，不重复整段长会话/废弃历史/所有原始工具回执；未来API逐次计量，缓存命中不能提前保证。

## 5. 同标准全页审核

沿用同一记忆点与7条件，先实际默认页、再交互补充；功能与审美分别报告。五宽度1440、2048、768、390、320，四状态，每边界25/50/75，桌面/手机各4任意位置，原生正反滚动、键盘、可信触摸、实际减少动态、禁脚本、资源、错误、溢出、正文裁切与可用行动全部检查。摄影上文字直接检查各裁切，不能用纯色对比度代替复杂图像区域。

通用工具`scripts/qa-page.mjs`按配置提供预期图数/字体/scene，120秒总期限、15秒单命令/连接期限，失败和超时写runtime及attempts。失效浏览器端点恢复任务浏览器后重试当前检查；不能记作页面通过。006特有菜单行为由其专项检查保留。自动检查只验证可观察行为，不自动给95。

**所有可见控件必须逐项审查交互状态。** 实现前列出按钮、筛选、输入、排序、菜单、展开说明及尺寸切换；按适用范围检查默认、悬停、键盘聚焦、展开、选中、空结果和异常状态。桌面与手机分别直接查看展开后的实际画面并留证，核对字体、配色、比例、选中标记、焦点、遮挡与边缘裁切。系统原生控件也必须展开审查，不能因原生实现而豁免。选择成功、截图生成和构建通过均不能替代视觉检查；有一项未检查，QA 状态就不能记为完成。

完整QA记录在docs/qa，完成后锁定源码指纹。运行例：`node scripts/qa-page.mjs <任务浏览器本地CDP> <QA配置> [gate|full]`。

2026-10-11补充：动态页另审鼠标离开/重入、滚动0/25/50/75/100%及反向、停止输入后的绘制、触摸替代和减少动态。正文逐段标用途，检查任意滚动位置是否被占位文字主导；以实际成品与001的过程质感对照，不能用淡入效果数量或内部评分代替。新候选不再优先静态处理，快筛须直接查看动态；简单工艺仍是条件，不是删掉动效的理由。

## 6. 一份包，两个资格

公开模板：视觉批准→完整QA/指纹→白名单私有staging→精确条目/字节→独立安装构建→公开包/条目→预览与HTTP哈希/长度校验。只有accepted条目进入public/templates.json，详见[下载标准](DOWNLOAD_STANDARD.md)。

完整工程试产：draft/trial、记录齐全、full QA/指纹通过后可用同一打包器`-Trial`与系统临时StagePath产一份私有ZIP，移入.webart/trials。没有95资格不能调用公开发布链；临时包校验后移走，不保留多个版本。可运行私人产物不等于主题展示。

## 2026-10-12 / 重做实测后的强制补充

以下约束用于每一份新稿，不只适用于006–008的修复：

2026-10-18新增强制项：每份静态计划加入 `performance` 四状态预算；实例化前确认已登记模板具有有效性能报告。完整QA后执行首次原生滚动、静态/动态、DPR2和CPU4手机压力、减少动态与后台20项实测，未通过不进入控件批准/打包。预算由 `webart.performance.json` 固定，不能让LLM决定优化手段或临场放宽。新风格原型阶段就应验证能否在预算内保持品质；通过后固定整页实现，普通配置不再重做3D。

1. brief逐段标记文字用途和长度：导航、作品名、必要说明、行动。默认每段说明最多两句，不用整屏长宣言/问答顶替图片或作品证据；实际首屏及任意滚动处直接复看文字占比。
2. reference map写明实际观察到的鼠标反馈和至少一个有视觉作用的滚动过程，以及触摸/键盘/减少动态替代。不得靠菜单与details数量宣称动态达标。正常动画检查显式设置`prefers-reduced-motion: no-preference`，随后单独设置`reduce`重测；记录真实变换/进度和停止输入后的稳定状态，防止继承浏览器偏好而漏测。
3. 素材先查`sourced-media.json`，新增图片仍先选现成摄影；锁定来源、许可、角色及桌面/手机裁切，实际原尺寸与最终页面都复看。每稿记录生成次数；本轮0生成只是获取方式，不是审美加分。
4. 四状态必须由同一可运行页面、最终素材和实际过程产生。内部批准记录具体画面依据与限制，不把95内评当用户验收。失败保留attempts；不适用的控件状态必须说明原因。
5. 完整QA后先产唯一私有包、独立安装构建，再按实际用户授权同步展示。请求“一稿供我审核”可授权这一稿的预览与下载，不自动变成用户视觉批准或未来稿授权。
6. 交付前在与启动不同的调用中检查首页、当前完整预览、所有本地素材、下载HTTP状态/长度/哈希，并记录监听进程与启动方式。不要把预览进程启动输出当服务持续可用。退出前再次健康检查；服务不可用不能称“可直接验收”。优先常规可恢复的本地启动方式；后台常驻若被权限审核拦截，明确保留手动启动方法，不能声称长期常驻已验证。

2026-10-12 / 010补充：页面整体不横溢不能证明内部控件完整。对设备框、卡片、菜单等有裁切容器的页面，逐项比较控件与其容器的实际边界；320窄屏原周格曾被内部overflow隐藏，已修复并加入配置化clipBounds检查。所有新增模板同时检查整体与内部裁切，不能只看scrollWidth。

这些规则减少已知漏项，不保证每次产出都获得用户认可。本轮009按此流程验证，视觉结果等待用户审核。

## 7. 计量与清理

每轮start/reference-locked/assets-ready/implementation-complete/qa-complete/complete标阶段；`scripts/production-meter.mjs <run> <stage>`只提取当前本地Codex用量，支持显式--session、私有--ledger。不读入报告会话正文或Key。实际API接入后须记录逐响应usage/缓存写入/服务等级/图像模型与完整费用，本地差值只是参考折算。

记录真实墙钟、执行间暂停、工具异常、素材等待、工具准备/修复和返工；共享初始化/优化/清理另计不摊藏在最有利样本。不可将暂停当生产耗时，也不能把技术异常从真实用户体验中抹掉。失败样本进入分母，不用模型自评宣称工业稳定性。

清理仅执行当前任务已授权且可明确归属的废弃或重复内容。保留冻结比较源、批准源码、唯一有效包、当前合同、紧凑QA、必要实测与拒绝索引，以及仍被合同、指纹或审核引用的图片和授权/审核收据；不得以旧清理段落删除不可覆盖的证据或他人工作。无引用的重复ZIP、临时副本和无用脚本才按范围处理；旧拒绝清理动作不由泛称清理恢复。实际清理前后核对本次受保护版本的源码指纹与ZIP哈希，不能沿用旧001/006名单推定当前范围。
