## 进入实际执行入口的约束

| 过去可能绕过的情况 | 现在的执行条件 |
|---|---|
| 只用总体七项peer判断整页 | visualContract锁定四状态的主体、材质、构图和视觉作用，独立审查须逐桌面/手机状态给出对应证据；明确损失强制reject |
| 用开场好看代评普通结尾 | 结尾只能引用该视口的结尾帧；引用开场、遗漏状态、只引一张图判断连续关系都被拒绝 |
| 同页总文字未超量，但某一屏全是说明 | 实际截图时测量可见文本，每状态桌面/手机分别锁预算；与总字数、段落预算同时执行 |
| 主体被隐藏、缩成装饰或重复 | 实际测量祖先隐藏/裁切后的可见范围与出现次数；不足即停止采证，不付费请求“看起来通过” |
| 关键3D每次由页面模型重新近似 | 关键模块须有绑定确切源码的素材准入、桌面/手机实图及作者/许可/分发依据。驱动器按SHA注入，模型只能调用接口，不能改src/locked或另建Three/WebGL代理 |
| 将批准模块放进源码包但省略使用 | 页面入口必须能静态引用到模块，构建及打包均检查；包内模块SHA再核验，渲染方式按实际源码检查 |
| 换稿号、名字或一份新高评价恢复旧失败 | 用户五个负样本按源码指纹阻断；三个实际拒绝试片进入持久登记。后续真实拒绝自动追加，审查文件按轮次独立保留；未改源码不再次请求付费视觉审查 |
| 文档提示词与实际模型规则不一致 | 运行器直接读取同一REVIEW_PAIR.md；前置母版门、试片门和打包门同时执行新合同 |

连续主体只在来源实际需要时配置；不会把摄影、建筑等不同设计全部强制为同一个连续仪表故事。可见范围、字数、代码引用和哈希只负责结构性拒绝，不能判断材质是否惊艳；材质、构图与交互品质仍需实际成对视觉审查。
