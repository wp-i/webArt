# 页面性能预算

2026-10-18，依据用户对Pace的实际反馈：视觉方向可以，但卡顿需要优化，否则减少实时3D内容。页面设计与工程化优先，复杂技术不加品质分。

普通媒体和HTML/CSS能保留参考作用时优先采用。只有材质、空间或形态确实需要实时渲染，才使用经过准入的局部模块；常规生产固定复制整页版本，不让模型每次重建场景或选择优化方式。性能合格不会补偿普通构图、弱素材或丢失核心交互。

静态计划的 `performance` 明确四状态为0或30帧。3D至少有一个静态状态，静止、减少动态及后台均停绘；DOM直接操控可独立刷新，不强制重画3D。Pace v2的展开与结尾停绘，开场/中段显示最多30帧，拖动由DOM响应。重复机械使用实例、线条按部件合并、材质转换只用同一表面；原部件细节与构图仍需视觉复核。

`webart.performance.json`固定两种压力配置：1440×900/DPR1/CPU1桌面；390×844/DPR2/CPU4手机压力。它不代表物理手机GPU测试。活动阶段主线程帧间隔P95上限分别34/50ms，P99为75/100ms，长任务100/160ms；全路径每帧至多100次绘制、360000三角形、4500000绘制像素。实时绘制采样上限31帧/秒，给30帧目标保留计时误差。

检查器在页面加载前包装浏览器原始WebGL方法，原样调用并计数；不依赖页面自己报告的三角形或帧数。首次进入先原生滚到真实结尾再返回，随后正常四状态、减少动态四状态、真实切后台，共20项。静止状态浏览器可自行降低合成回调频率，因此只在活动阶段判断帧间隔；静止阶段要求0GPU绘制及无超预算主线程长任务，不把省电行为误判为卡顿。

运行器和整页回放实际执行测量，登记和打包重新核验报告的源码、政策指纹、静态计划、完整状态和全部指标；不能只改 `result` 或重算报告SHA放行。默认运行器采用同一性能门。已拒或未通过的方案先修改受版本控制的共享模块并重新准入，仍不合格就减少实时3D范围，不提高预算。原v3只在精确历史合同路径可读，不得复制到新目录重新登记或打包。

新模板在四状态试片阶段即确认能在预算内保留视觉作用，完整QA再复测。原型未过预算，不应先扩成整页。用户设备仍卡顿时继续以实际反馈校准，不能用本机压力通过代替验收。
